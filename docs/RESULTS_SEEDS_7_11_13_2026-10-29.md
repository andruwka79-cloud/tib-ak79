## What the numbers support
- Llama: the notice (C, D) lifts the score by about 0.21 and its interval does not cross zero; the gate alone (B) changes nothing. D adds nothing over C in the mean (0.479 vs 0.479).
- Qwen: A, B, C are within 0.01 of each other. D is +0.051 over A, but the interval includes zero, so this is a tendency, not an established effect. Qwen A has 3 harm runs in every seed; B, C, D have none.
- D versus C by task, averaged over the three seeds: Qwen D is higher on 6 tasks and lower on 4 (largest gains +1.0 on two tasks, largest loss -0.78), Llama D is higher on 1 and lower on 3, and the sum of differences is about zero. The per-task picture does not show a reliable reviewer effect for Llama.
- "Sign flips across seeds: yes" for B (both models) is noise around a zero difference (differences of a few thousandths).

## Data integrity and caveats
- Llama D, seed 7: 3 of 120 runs had reviewer errors (the cause was not checked; the run used 300/600 s timeouts) and fell back to arm C behaviour, so the report flags them. A rerun of that arm with longer timeouts (900/1800 s, "d2", mean 0.479) exists but has a different `model_config`, so it is not part of the table; seeds 11 and 13 ran with 300/600 s and had 0 reviewer errors.
- Seeds 11 and 13 were run twice by the operator (an earlier set on 2026-10-27 morning, a later set in the evening). The indexed (later) set is used here. For Qwen the two sets give the same means to three decimals; for Llama arms A, B, C the earlier set is lower (for example seed 11 arm A 0.242 vs 0.267), arm D equal. The cause of the difference was not established; it is not hidden by choosing the indexed set.
- Hashes: the 16 indexed result files for seeds 11 and 13 match the operator's index (sha256 of the original Windows files, CRLF line endings). Git stores them with LF endings, so a hash of the committed bytes differs; it matches after converting LF to CRLF. Seed 7 files are the ones from [the one-seed document](RESULTS_QUAD_QWEN3_LLAMA31_2026-10-27.md).
- Small local models, one open task set, one machine. Not verified: other hardware, other Ollama versions, the closed task set.
